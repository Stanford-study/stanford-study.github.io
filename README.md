# ABC Tutoring

A small tutoring website built with HTML, CSS, JavaScript modules, and native Web Components. No runtime framework, dependencies, or compilation required. GitHub Pages serves the site; bookings stay in the visitor's browser.

## Run locally

Run `npm run dev`, then visit `http://127.0.0.1:8000`. Node 20+ runs the tests/build; Python 3 serves local files. Opening `index.html` directly does not support fetching JSON/modules.

- `npm test` checks booking persistence, validation, duplicates, telemetry privacy/failure handling, and email preview output.
- `npm run build` validates the tutor data and copies only public assets into `dist/`.
- `node scripts/check-posthog.mjs` checks the configured PostHog host/token and sends one `integration_check` test event.
- `npm run test:traffic` requests local static assets 45 times with three concurrent workers and reports failures and p95 latency. Optional: `-- --url https://stanford-study.github.io/ --requests 45 --concurrency 3`. This is a small HTTP smoke test, not proof of browser performance or multi-user booking correctness.
- `npm run demo:posthog` sends 15 clearly labeled synthetic visitor journeys: 15 pageviews, 10 booking starts, and 5 completions. Filter PostHog to `environment = demo` to explore these events, or `environment = production` to exclude them. No bookings are saved and no emails are generated by this script.

## Edit tutors and sessions

Edit `data/tutors.json`. The names are fictional examples. Each tutor has `id`, `name`, `subjects`, `grades`, and `availability`. Grade `0` means kindergarten. Each slot has a unique `id` and ISO start/end timestamps with UTC offsets. `timeZone` controls display.

Keep IDs stable after bookings exist. Add future dated slots as the sample dates pass; expired or locally booked slots are hidden. Slots are initial inventory, not shared reservations. Clearing browser data removes bookings. Web Locks serialize bookings across tabs where supported; other browsers have best-effort duplicate protection. Different devices do not synchronize.

## Email stub

Set `notifications.recipientEmail` (Dana) and `notifications.senderEmail` in `js/config.js`. They are intentionally blank until real addresses are available. Mode remains `stub`.

After a booking is saved, `sendBookingNotification` builds the email and prints `[EMAIL STUB — not sent]` in the browser's developer console with `to`, `from`, `subject`, and `body`. The body includes the tutor, session, parent email, student grade, and booking reference. Unconfigured addresses appear as explicit placeholders. This is a developer preview, with no network request or actual delivery. It returns `{ status: "stubbed", delivered: false, ... }`.

Notification failure does not undo the booking. To send real email later, replace the adapter with a call to an external delivery endpoint and update confirmation copy. Changing the addresses or mode alone does not enable real delivery. Provider secrets belong on that service, never in the browser or this public repository.

## PostHog

The provided public project token is configured in `js/config.js`, using `https://us.i.posthog.com`. For an EU project, change `apiHost` to `https://eu.i.posthog.com`. Set `enabled: false` to disable SDK loading entirely.

The official browser SDK loads asynchronously only when configured. The adapter queues early events and makes analytics independent of bookings. Explicit events are `$pageview`, `subject_selected`, `tutor_viewed`, `booking_started`, `slot_selected`, and `booking_completed`. A tutor view means at least half the card was visible for one second; it is counted once per tutor per page load. Booking starts are counted once per tutor per page load. Completion fires only after local persistence succeeds.

Autocapture, replay, surveys, flags, and automatic pageviews are disabled. An allowlist strips email, grade, form data, initial URLs, and arbitrary SDK properties before events leave the browser. Only safe UTM tags, referrer hostname, a query-free page URL, anonymous identifiers, device metadata, and the event's subject/tutor/slot fields are retained. Email console previews are not sent to PostHog.

Localhost events have `environment: development`; hosted visits have `environment: production`. Filter reports to production. In PostHog, create:

1. A funnel: `$pageview` → `booking_started` → `booking_completed`, using unique users and a same-session filter if desired.
2. Subject interest: `subject_selected`, broken down by `subject` (exclude `All subjects`).
3. Tutor exposure: `tutor_viewed`, broken down by `tutor_id`; compare with `booking_started`.
4. Acquisition: `$pageview` and completed bookings broken down by `utm_source` and `utm_campaign`.

Share `https://stanford-study.github.io/?utm_source=facebook&utm_medium=social&utm_campaign=parent_group` in the Facebook group. Funnel drop-off estimates abandonment; there is no browser-close event. Ad blockers can prevent collection. A capture-endpoint response verifies acceptance, not that a dashboard/report was created. The public project token cannot create dashboards or query private analytics.

## GitHub Pages

`.github/workflows/pages.yml` tests and publishes the public `dist/` files when `main` changes or when run manually. Select **GitHub Actions** under the repository's **Settings → Pages → Build and deployment**. The intended URL is `https://stanford-study.github.io/`. Relative asset paths also support a repository subpath.

The page starts directly with tutor discovery. Slots and grades use native radio controls; no dropdowns, expandable profiles, introduction, or cancellation interface is included. Responsive CSS uses a booking sidebar on desktop and a single column on phones. Optional WebMCP tools expose listing sessions and opening the booking form in supporting browsers; they cannot submit or read saved parent details.
